# dsh-desktop 项目规划

> 版本：v1 · 2026-08-16 · 本文档是项目的长期路线图，随项目演进更新。

## 1. 项目定位（一句话）

**DeepSeek Harness 的 Windows 桌面壳，核心差异点是「选区截图直接问 AI」——让纯文本的 dsh 也能看图。**

- 不跟 Tauri 壳 / WebView2 壳拼「轻量」，拼「截图→提问的完整闭环体验」
- 不改 dsh 本体，纯壳零侵入
- 当前已发布 v0.2.8，已收录 awesome-dsh-plugin，plugin 子包已发 npm

## 3. 产品方向（做什么）

### 3.0 对标参考（2026-08-16 调研）

同类桌面壳中最强的：**xiincs/deepseek-harness-desktop**（Tauri 2 + Rust，46 star）。它的 README 有 5 个值得借鉴的点，列入产品/文案方向：

| 借鉴点 | 它的做法 | 咱们的对应 |
|---|---|---|
| 顶部大字卖点 | 「不用再守着浏览器标签页」一句话打动 | README 顶部同样一句话定位 |
| 演示截图/GIF | 顶部放运行截图，注释里预留 GIF 占位 | README 顶部放选区截图 GIF |
| 「崩溃自己爬起来」 | 服务挂了自动重启 + 说明原因 | 近期必做：dsh 进程崩溃自动重启 |
| 「有新版会提醒」 | 打开时自动检查更新，一键装 | 近期必做：自动更新检查 |
| 常见问题 FAQ | 数据安全/离线/非官方说明，消除疑虑 | README 加 FAQ 段 |

> **竞争定位（校准后）**：xiincs 功能面更全（文件面板/内置终端/自动更新/崩溃自愈都是实打实的功能），但**没有「选区截图提问」**——这是咱们独有的完整闭环。策略不是「不冲突」，而是：**用「截图提问」这个独有点做尖刀，同时补上「自动更新/崩溃自愈」这类刚需底座**，避免用户因缺基础体验而流失。

### 3.1 差异化主线：把「选区截图提问」做到极致

- 这是唯一别人没有的完整闭环（GPU 框选 + 自动粘贴 + 识图让纯文本模型看图）
- 所有新功能优先问：「它让截图提问更好用吗？」
- 竞争策略：**尖刀（截图提问）+ 底座（自动更新、崩溃自愈、稳定识图）**双线并行——尖刀赢差异，底座赢信任

### 3.2 路线图（按优先级）

**近期（v0.3 目标，按「竞品差距优先」排序）**
- [ ] **🥇 自动更新检查**（启动时检测 GitHub Releases 最新版，有新版提示一键引导）——竞品已有，刚需底座
- [ ] **🥈 dsh 进程崩溃自动重启**（检测服务挂掉 → 自动拉起一次 + 提示原因）——竞品已有，刚需底座
- [ ] **🥉 识图稳定性**：处理 GLM-4V-Flash 偶发 JSON 不完整（重试/降级/换模型提示）
- [ ] 截图后的快速操作：选区确认后可选「提问/复制/保存」三个动作
- [ ] 演示 GIF / 截图素材入库（README 顶部 + 推广用）

**中期（v0.4）**
- [ ] 截图按钮放进聊天框 "+"（官方 slot `conversation.input.left`）——优化项，非刚需；保留全局按钮，双入口

- [ ] 截图历史（最近 N 张，可重发）
- [ ] 设置面板（截图快捷键、识图模型选择、开机自启）
- [ ] FAQ 段落入 README（数据安全/非官方/离线说明，消除疑虑）

**远期（候选）**
- [ ] 中文本地化完善 / 多语言
- [ ] 插件化截图工具（OCR、翻译、表格识别）
- [ ] 反馈渠道（内置「提交 Issue」入口）

### 3.3 明确不做（聚焦）

- 不做 macOS / Linux 版（保持 Windows 精品）
- 不重复造 dsh 已有的功能（会话、模型选择等交给 dsh 本身）
- 不做「全家桶」式功能堆砌

## 5. 维护策略（留得住人）

- **响应**：issue 当天回复（哪怕说「下版修」）
- **发版**：有实质改进就发，不憋大招；每次发版写清 changelog
- **发布流程**：bump version → push → tag → npm publish → GitHub Actions 自动 Release（见交接文档）
- **质量**：发布前必自检（npm 实装加载测试、工作区干净、远程一致）
- **清理**：定期清 build-out 旧版本，别堆垃圾

## 7. 风险与对策

| 风险 | 对策 |
|---|---|
| 竞品多（Tauri/WebView2 壳）| 死磕截图提问闭环，不打价格战/轻量战；补齐自动更新/崩溃自愈等刚需底座 |
| 竞品功能面更全（xiincs 有文件面板/终端）| 截图提问做尖刀 + 明确不做全家桶；若用户反馈强烈，文件面板列入远期评估 |
| 识图依赖智谱免费模型，偶发不稳 | 重试 + 提示换 glm-4v-plus + 后续做模型选择 |
| 新项目无口碑 | 靠演示 GIF 的视觉冲击 + 精准渠道（V2EX/知乎）|
| 密钥泄露风险 | 智谱 key / npm token 绝不进聊天；轮换机制写进交接文档 |
